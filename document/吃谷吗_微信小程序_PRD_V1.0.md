# 1. 文档概述
## 1.1 文档目的
本PRD用于统一定义“吃谷吗”微信小程序V1.0的产品目标、业务范围、页面结构、功能行为、数据关系、统计口径、异常处理、非功能要求及验收标准，为产品、UI/UX、前端、后端、测试及项目管理提供同一份需求基准。
## 1.2 产品定位

| 一句话定位<br>面向二次元用户的消费与收藏管理工具。 |
| --- |


核心价值：让二次元用户清楚知道自己在什么时候、哪个作品/IP上、以什么方式，花了多少钱，同时建立自己的消费与收藏档案。
## 1.3 核心用户
V1.0核心用户为同时存在谷子消费与游戏氪金行为的重度二次元用户。
经常购买谷子、周边、同人创作或相关商品。
经常进行游戏抽卡、直购、月卡或礼包等消费。
拥有一定数量的收藏，并可能存在预售商品。
随着消费增加，开始难以掌握自己到底花了多少、买了什么、哪些还没收到。
## 1.4 核心目标

| 目标 | 说明 |
| --- | --- |
| A：知道花了多少钱 | 按时间、IP、消费方式等维度查看二次元消费。 |
| B：记录买过什么 | 形成完整的谷子/周边消费档案。 |
| C：统一管理二次元消费 | 将谷子与游戏氪金纳入统一账本，同时分类管理。 |
| D：了解作品/IP消费 | 支持按IP、角色等维度进行分析。 |
| E：控制消费 | 通过用户自主预算和事实提醒了解消费状态。 |
| F：管理收藏 | 维护当前收藏及历史曾拥有记录。 |


## 1.5 核心使用闭环

| 发生消费 → ＋记一笔 → 沉淀消费/收藏/预售数据 → 查看首页反馈 → 进入统计分析 → 获得消费洞察 → 再回来记录 |
| --- |


## 1.6 产品核心原则
先记账，再完善：低频字段不得阻塞保存。
一次输入，多处使用：一次消费记录可以同时沉淀消费、收藏和预售数据。
消费与收藏有关联，但不强绑定。
预售独立于收藏，收藏不记录到货状态。
首页看结果，统计页做分析。
预算由用户主动开启并自主设置提醒程度。
产品不参与交易，不承担电商、导购或物流系统职责。
历史消费记录优先保证完整性，业务关联删除不应意外破坏其他业务数据。

# 4. 功能需求
## 4.1 首页
### 4.1.1 首页定位
首页承担“消费状态总览 + 高频操作入口”。用户进入后优先看到当前消费状态，而不是复杂分析。
### 4.1.2 本月消费
展示当前月份的总消费，并拆分谷子与游戏氪金。

| 9月消费<br>¥2,386<br>🛍️ 谷子 ¥1,286<br>🎮 游戏 ¥1,100 |
| --- |


### 4.1.3 消费趋势
展示本月每日实际消费折线图。
无消费日期显示¥0，不跳过日期。
同时显示本月与上月消费对比。
首页趋势纯展示，不进入统计下钻。
### 4.1.4 待收到
存在待收到预售时，首页只显示简洁数量，例如“📦 待收到 3 件”。点击进入预售管理。首页不展开具体商品。
### 4.1.5 最近消费
展示最近3条消费记录，使用极简信息。
### 4.1.6 预算摘要
预算未开启时不显示预算模块；开启后常驻首页。总预算存在时优先展示总预算状态，分类预算在预算详情页查看。
### 4.1.7 快速记账

| ＋ 记一笔<br>🛍️ 谷子 / 周边<br>🎮 游戏氪金 |
| --- |


## 4.2 消费
### 4.2.1 模块定位
消费页负责统一查看、记录、编辑和删除二次元消费。谷子与游戏氪金统一进入账本，但按一级消费类型分类管理。
### 4.2.2 消费类型

| 类型 | 定义 |
| --- | --- |
| 谷子 / 周边 | 游戏、动漫等IP相关官方或同人创作、周边及商品消费。 |
| 游戏氪金 | 游戏内抽卡、直购、月卡、礼包、赠送等实际支付行为。 |


### 4.2.3 ＋记一笔流程
先选择消费类型，再填写对应字段。基础流程优先保证10～20秒完成。
### 4.2.4 谷子基础字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 商品名称 | 是 | 自由输入；可复用个人词库。 |
| 单价 | 是 | 用于自动计算总金额。 |
| 数量 | 是 | 表示用户购买的商品单位数量，不表示套组内部实物件数。 |
| IP | 是 | 自由输入并自动建立个人词库。 |
| 商品图片 | 否 | 完全可选，可随时补充。 |


### 4.2.5 谷子更多信息
角色：可选，支持默认单角色，需要时添加多个。
商品类型：可选，固定常用选项 + 用户新增。
购买渠道：可选，固定常用渠道 + 用户新增。
官方/同人：可选，官方 / 同人 / 不填。
预售：可选；勾选后填写预计出荷时间。
是否加入收藏：由用户主动选择。
备注：可选。
### 4.2.6 商品类型默认选项
吧唧、亚克力立牌、徽章、色纸、手办、毛绒、同人本、其他；允许用户新增个人类型。
### 4.2.7 购买渠道默认选项
淘宝、京东、闲鱼、官方商城、线下店、展会、同人摊位、其他；允许用户新增个人渠道。
### 4.2.8 金额与数量

| 数量定义<br>数量 = 用户购买的商品单位数量。例如“芙宁娜A款吧唧×3”数量为3；“芙宁娜A款吧唧套组×1”数量为1，即使套组内部有3个吧唧，也不将购买数量记为3。 |
| --- |


谷子总金额 = 单价 × 购买数量。消费详情与统计均以当前保存的总金额为准。
### 4.2.9 游戏氪金

| 字段/原因 | 规则 |
| --- | --- |
| 游戏名称 | 必填；自由输入并自动建立个人游戏词库。 |
| 金额 | 必填；记录实际支付金额。 |
| 抽卡 | 直接记录实际支付金额。 |
| 直购 | 直接记录实际支付金额。 |
| 赠送 | 直接记录实际支付金额。 |
| 月卡 | 允许单价×数量。 |
| 礼包 | 允许单价×数量。 |
| 备注 | 可选自由备注。 |


### 4.2.10 更多信息交互
低频字段采用“更多信息 ▼”折叠。默认展示核心字段；预售勾选后才显示预计出荷。
### 4.2.11 消费日期
默认今天。
允许修改为今天或过去日期。
不允许未来日期。
不要求精确到时分。
预售商品按实际付款日期进入消费统计。
### 4.2.12 消费列表
顶部固定显示当前月份汇总：总消费、谷子消费、游戏氪金消费。月份支持左右切换，并可点击月份直接选择年月；未来月份不可选择。
### 4.2.13 消费列表展示

| 🛍️ 芙宁娜吧唧 ×2<br>¥70<br>9月24日<br><br>🎮 原神 · 月卡<br>¥30<br>9月22日 |
| --- |


默认不展示角色、商品类型、渠道、官方/同人、备注、预售及收藏状态。
### 4.2.14 消费详情
顶部突出展示“商品/游戏 + 金额”，下方展示完整字段、预售、收藏、备注及编辑/删除操作。
### 4.2.15 消费编辑
点击编辑进入与首次记账相同结构的完整表单。保存后返回详情页。修改后只保留当前值，不记录修改历史。
### 4.2.16 消费删除
删除必须二次确认。若存在收藏或预售关联，提示用户选择仅删除消费或同时处理关联数据。若无关联，则直接执行普通二次确认。
### 4.2.17 ¥0消费
¥0消费记录允许存在。
仍保留收藏、预售及关联关系。
不参与任何统计。
¥0不等于删除。
## 4.3 收藏
### 4.3.1 收藏定位
收藏模块是“当前拥有 + 历史曾拥有”的管理工具，与消费记录关联但不等同。
### 4.3.2 收藏创建
消费时选择“加入收藏”：一次录入同时产生消费与收藏数据。
独立添加收藏：不要求存在消费记录。
独立收藏最低信息为商品名称、数量、IP。
开始拥有日期默认今天，可修改为过去日期，不允许未来日期。
### 4.3.3 收藏数量模型

| 指标 | 含义 | 变化规则 |
| --- | --- | --- |
| 当前拥有 | 当前实际拥有数量 | 可增加、减少、直接编辑；最低为0。 |
| 曾拥有 | 历史累计进入收藏的数量 | 只增加，不因减少收藏而减少。 |


### 4.3.4 数量操作
支持＋/－快速调整。
支持点击数量直接编辑最终数量。
减少数量不能超过当前拥有数量。
数量归零后进入收藏历史。
### 4.3.5 收藏历史
收藏历史保留商品、IP、角色、类型等信息，并展示曾拥有数量。再次获得同款时恢复原收藏对象。

| 曾拥有 ×3 / 当前 ×0<br>再次获得 ×2<br>→ 曾拥有 ×5 / 当前 ×2 |
| --- |


### 4.3.6 收藏与消费关联
系统维护“消费记录对收藏的数量贡献关系”。例如消费A贡献×2、消费B贡献×3，则当前收藏可能为×5。编辑或删除消费时，可根据这笔消费的实际贡献数量同步调整收藏。
### 4.3.7 消费数量编辑同步
修改消费数量时，不自动改变收藏；系统询问是否同步。用户选择同步后，只调整该消费记录对收藏的贡献数量。
### 4.3.8 重复购买
消费记录永远独立保留；收藏端可能合并。同款判断综合商品名称、IP、商品类型、角色等信息，并由用户确认是否合并。
### 4.3.9 收藏页面
默认网格展示。
支持切换列表展示。
两种模式使用同一数据。
V1.0暂不提供收藏搜索。
### 4.3.10 收藏筛选
统一筛选面板：IP、角色、商品类型；提供重置与确定。
### 4.3.11 收藏详情

| 芙宁娜吧唧<br>❤️ 当前收藏 ×3<br>📚 曾拥有 ×5<br>IP：原神<br>角色：芙宁娜<br>类型：吧唧<br>开始拥有：2026/09/01<br><br>关联消费<br>9月1日 ×2 ¥70<br>9月20日 ×1 ¥30<br><br>[＋增加数量]<br>[－减少数量] |
| --- |


关联消费只显示仍存在且仍关联的消费记录。消费删除或解除收藏关联后，不再显示。¥0消费仍显示在收藏详情的关联消费中，因为它仍是存在的业务记录。
## 4.4 预售管理
### 4.4.1 定位
预售管理用于提醒“还有哪些买了但没收到”，不承担订单、物流或商家状态管理职责。
### 4.4.2 创建
保存消费记录时勾选预售并填写预计出荷时间，系统自动创建独立预售记录。
### 4.4.3 数量
默认继承消费数量，但允许修改。因此一笔消费×3可以只有预售×2。
### 4.4.4 状态
仅有两种状态：待收到、已收到。
### 4.4.5 部分到货
不记录部分到货数量。只有整笔预售全部收到后，才能标记为已收到。
### 4.4.6 预计出荷
允许过去、今天、未来日期。
日期过去不会自动改变状态。
已收到后仍可修改预计出荷。
不记录实际收到日期。
### 4.4.7 与收藏解耦

| 独立关系<br>购买时选择加入收藏即确定收藏关系；后续到货不会再次询问收藏，也不会改变收藏状态。预售状态不进入收藏页面。 |
| --- |


### 4.4.8 入口
首页：仅显示待收到数量，点击进入管理。
完整入口：我的 → 预售管理。
### 4.4.9 管理页面

## 4.6 预算管理
### 4.6.1 定位
预算用于让用户了解消费与预算之间的关系，不参与交易，也不强制阻止用户消费。
### 4.6.2 默认与开启
默认不开启。用户主动进入预算设置后开启，不主动弹出预算引导。
### 4.6.3 周期
支持周、月、年。
### 4.6.4 预算类型
总预算。
谷子预算。
游戏氪金预算。
三类预算独立判断、独立开启/关闭、独立计算提醒。
### 4.6.5 阈值
用户可选择80%、100%、超预算，可多选。每个阈值每个周期最多提醒一次。
### 4.6.6 首页提醒
仅在小程序内提示。
不发送微信订阅消息。
直接展示在首页预算模块。
不使用弹窗。
### 4.6.7 状态优先级
只显示更高一级的最新状态：达到80%→100%→超预算。状态持续到周期结束，新周期重新计算。
### 4.6.8 预算修改与关闭
修改当前周期预算后立即重新计算。
预算可随时关闭。
关闭后停止计算、停止提醒、首页隐藏预算模块。
关闭不删除配置及历史。
重新开启恢复上一次预算金额。
关闭期间产生的消费不参与该预算计算。
### 4.6.9 金额规则
预算允许设置为¥0，¥0为有效预算而非关闭；金额允许精确到小数点后两位，不允许负数。
### 4.6.10 预算历史
保留最近一年，最多12个月历史周期。预算页展示当前进度、历史周期和趋势图；统计页负责消费本身的分析。
## 4.7 个人词库
### 4.7.1 词库类型
IP、游戏名称、角色、商品类型、购买渠道。
### 4.7.2 建立机制
用户首次输入新名称后自动建立个人词库，后续输入优先推荐，同时始终允许新建。
### 4.7.3 管理
支持查看、修改、删除。
修改名称直接覆盖，不保留别名，并同步更新历史业务数据。
删除只移除当前词库可选项，不删除业务数据。
不做置顶或排序。
### 4.7.4 重复与恢复
同名自动识别，不创建重复词条。
删除后再次使用相同名称，恢复原词条关系。
清空词库后，历史业务数据仍保留原文字；再次使用时按既有业务关系恢复，若历史从未出现则创建新词条。
### 4.7.5 删除确认
删除词库词条需要二次确认，明确说明不会删除历史业务数据。

# 5. 业务规则与数据规则
## 5.1 字段与词库规则
IP自由输入并自动建立个人词库。
游戏名称与IP采用同一类自由输入+个人词库机制，但统计时名称不自动跨名称关联。
角色默认单选，需要时允许添加多个。
商品类型、购买渠道均为固定常用项+用户新增。
官方/同人为可选字段。
## 5.2 数量规则

| 数量对象 | 含义 |
| --- | --- |
| 消费数量 | 用户购买的商品单位数量。 |
| 预售数量 | 默认继承消费数量，可独立修改。 |
| 当前收藏数量 | 当前实际拥有数量。 |
| 曾拥有数量 | 历史累计进入收藏的数量，只增不减。 |


## 5.3 收藏贡献规则
系统维护每笔消费对收藏的实际数量贡献。消费数量修改时是否同步收藏由用户决定；删除消费时按照这笔消费当前贡献数量处理。
## 5.4 日期规则

| 日期 | 允许范围 |
| --- | --- |
| 消费日期 | 今天及过去 |
| 开始拥有日期 | 今天及过去 |
| 预计出荷时间 | 过去、今天、未来均可 |


## 5.5 删除规则
消费删除需要确认；存在关联收藏/预售时需用户选择处理方式。
预售删除不影响消费和收藏。
收藏数据调整不删除消费。
词库删除不删除业务数据。
清空业务数据不清空个人词库。
## 5.6 统计规则
统计金额直接使用消费记录当前保存的总金额。
¥0消费完全排除在统计之外。
IP占比分母为当前统计范围内全部有效消费金额。
未填写IP计入总额与占比分母，但不占真实IP排名名额。
Top5只针对真实IP；真实IP超过5个时才显示其他。
## 5.7 预算规则
总预算、谷子预算、游戏预算独立计算。
未设置的预算不参与提醒。
关闭预算不删除配置。
重新开启恢复上次金额。
关闭期间消费不参与该预算。
# 6. 非功能需求
## 6.1 数据存储与持久化
使用微信云开发进行数据存储。用户业务数据与微信小程序用户身份关联，重新进入小程序后读取云端数据。
## 6.2 用户数据隔离
用户只能访问与自身微信身份关联的数据，不同用户之间必须严格隔离。
## 6.3 离线能力
联网正常时直接写入云端。
网络异常时允许本地暂存。
恢复网络后自动同步。
离线多笔数据逐笔同步，不合并。
## 6.4 同步可靠性
同步失败不得删除本地数据。
失败数据保留待同步队列并自动重试。
首页显示待同步数量。
全部同步成功后待同步状态消失。
## 6.5 数据一致性
金额、收藏贡献、预售关联、预算计算及统计口径应集中处理，避免同一规则在多个页面重复实现造成不一致。
## 6.6 可用性
核心记账流程应在移动端保持连续、简洁。
高频记录路径控制在10～20秒完成基础记录。
高风险操作必须二次确认。
空状态应提供明确的下一步操作。
## 6.7 可维护性
业务规则、统计口径、数据关系应以统一服务/规则层实现；页面层只负责展示和交互，避免页面自行重新计算核心业务数据。
## 6.8 数据导出可理解性
导出数据以用户能理解的业务字段为准，不向用户暴露内部ID、内部关联表或技术实现细节。
# 7. 交互与体验要求
## 7.1 首次使用
首次打开显示简短三步新手引导：1.记录消费；2.管理收藏；3.查看分析。允许右上角跳过。完成或跳过后不再显示。
## 7.2 快速记录
记录流程优先询问核心必填字段，低频字段折叠。保存后用户可以在详情页继续完善。
## 7.3 统一操作语言
新增：＋
删除：删除 + 二次确认
编辑：进入完整表单
收藏：加入收藏/从收藏中调整
预售：待收到/已收到
预算：达到提醒线/超预算
## 7.4 空状态
空状态应说明“当前没有什么数据”以及“用户下一步可以做什么”，避免仅显示空白页面。
## 7.5 统计交互
图表默认不堆叠过多数字标签。
数据点交互时显示日期+金额。
统计下钻必须保留上下文条件。
返回统计页时尽可能恢复用户原来的位置与条件。

本月总消费与谷子/游戏拆分正确。

总金额正确计算。

勾选预售后可填写预计出荷。

支持本周、本月、本年、自定义。
累计/实际消费切换正确。
